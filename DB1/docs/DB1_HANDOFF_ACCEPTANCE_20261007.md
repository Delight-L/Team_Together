# DB1 인수 검증 결과 · 2026-10-07

## 전달 결과

실제 2025년 신호 3건의 설명 예시, 읽기 전용 조회 도구, 분리 DB 업데이트 검증 기록을 추가했다. 운영 DB에 모의 자료를 넣지 않았다. 원천 정의 정정 문서와 설명 규칙을 함께 읽는다.

- 실제 설명 예시: `docs/AI_AGENT_HANDOFF.md`, 기계가 읽는 근거: `outputs/handoff/agent_explanation_examples.json`.
- 조회 도구: `tools/read_agent_context.py`. 동일 기준월의 활동 추적과 조사·독거노인 배경을 결합한다. 미래의 최신 추적값을 과거 질의에 암묵적으로 붙이지 않는다.
- 모의 검증: `outputs/validation/handoff_20261007/UPDATE_ACCEPTANCE_SYNTHETIC.json`. 통계 분석 결과로 사용하지 않는다.

## 순서별 확인

1. 역삼2동 40대(소비 감소 겹침), 삼성2동 30대(소비 방향 엇갈림), 역삼2동 30대(분기 기간 불일치)를 운영 DB에서 조회해 설명 예시를 작성했다. 모두 소통 신호이며 이동·결합 신호는 없다. SNS 시간 비교와 고립 확정 표현을 사용하지 않는다.
2. 기존 운영 DB를 별도 작업 폴더로 복제했다. 2025-12 원천 성별·5세 그룹 자료를 바탕으로 만든 모의 2026-01·02 기준 파일과 완전한 모의 2026-01 카드 CSV를 실제 입력 경로와 같은 형식으로 처리했다. 통신 역삼2동 30대의 소통·이동만 0.25배로 줄이고 관심집단 비율은 0.7로 설정했다. 모의 기상 입력은 실행용 키를 제공하며 실제 기상이나 공휴일 보정을 검증하지 않는다.
3. 신규 원천 셀 2,112행 → 서비스 연령 특징 220행 + 5세 특징 528행 → 연령 탐지 220행 → 카드 1개 월 적재 → 관측 기간 정렬과 통합 조회를 확인했다. 의도한 모의 역삼2동 30대 1건에 결합 신호가 발생했다. 이는 정확도 측정이나 새 실제 고립 사례가 아니다.
4. 원래 44개 테이블의 모든 행이 테스트 DB에 동일하게 존재했다. 기준 모델도 유지됐다. 반복 scan 전후 전체 테이블 저장값이 같았고 DB 무결성·외래키 검사를 통과했다. 실제 DB 조회 예제는 기존 신호 10건을 반환했다.

## 기간 연결

2026-01 기준 통신은 2025-10~12월 관측이므로 2025Q4 상권에 연결했다. 2026-02 기준은 2025-11~2026-01월 관측이므로 분기 상권 변화는 NULL이며 모의 2026-01 카드가 관측 창에 포함됐다. 신규 월 카드가 있다고 모든 도메인의 완전한 6개월 비교가 가능해지는 것은 아니다. 업종·일수·이전 창 부족의 NULL을 유지한다.

## 이번에 검증하지 않은 항목

실제 2026년 원본 데이터, Analysis1 2026H1 새 반기 산출, 새 연도 조사 적재, 외부 원본 자동 다운로드, 원천 실제 공개일, 공휴일 규칙, 사회적 고립 정답 기반 성능은 검증하지 않았다. Analysis1은 저장된 2025H2 맥락을 재사용했다. 2026H1은 반기 입력이 완전하고 공공자료 시점이 확인된 뒤 별도로 실행해야 한다. 기존 조사 통계는 복사된 사후 배경이며 조사 수집을 재실행하지 않았다.

## 팀원에게 전달할 구성

`DB1` 전체 폴더를 전달한다. 읽기 전용 질의에는 `outputs/db1.sqlite`, 조회 도구와 해석 문서만으로 시작할 수 있다. 재분석·업데이트에는 세 분석 코드, Context, db/schema.sql, 기준 모델, 기준/reference 파일, 설정과 외부 원본 폴더가 필요하다. 문서만 전달하면 업데이트할 수 없다. 설정의 두 JSON(`config/db1_config.json`, `Analysis3/config/analysis3_config.json`)에서 팀원의 원본 경로를 수정한다. 고정 기준 모델은 재학습하지 않는다.

기본 PowerShell 실행 환경은 `C:\ProgramData\anaconda3\envs\analysis1\python.exe`다. 팀원 환경에서는 `run_db1.ps1 -Python <경로>`로 지정한다. 필요한 패키지는 루트 requirements.txt를 확인한다. 읽기 도구는 Python 표준 라이브러리만 사용한다. 라이브러리 확인은 설치·최신 환경 호환성 보장이 아니며 검증한 버전 목록을 함께 제공한다.

운영 DB에 대한 실제 상태 조회와 전달 도구 검증은 `outputs/validation/handoff_20261007/DELIVERY_CHECK.json`을 참조한다. 실제·모의 자료를 구분하고 설명에 사용할 조회 결과에는 모델 버전, 원천 기준월, 실제 관측 창, 판정 가능 여부, NULL과 공개일 미확인을 보존한다.
