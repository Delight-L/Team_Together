# PostgreSQL 전환·파일 정리 기록

2026-10-19 기준 분석·전처리·서비스 DB 경로를 PostgreSQL로 통일했습니다.
작업은 `codex/postgresql-only` 브랜치에 있으며 서비스의 활성 분석 버전은 변경하지 않았습니다.

## 데이터 보존

| 작업 영역 | 원본 테이블 | 보존 행 | 조회 뷰 |
|---|---:|---:|---:|
| `db1_pipeline` | 61 | 120,414 | 27 |
| `db1_regional_archive` | 46 | 44,665 | 11 |
| 합계 | 107 | 165,079 | 38 |

테이블마다 전체 행을 순서에 무관한 SHA-256으로 비교했습니다. 모든 테이블이 일치했습니다.
뷰 36개는 JSON 표현을 정규화한 값이 일치했습니다. 나머지 2개는 JSON 실수 직렬화 자릿수가 달라
객체·배열 식별자와 모든 값을 별도로 대조했습니다. 상대 오차 `1e-14`, 절대 오차 `1e-15` 안에서 일치했고,
최대 절대 차이는 `4.547473508864641e-13`입니다. PostgreSQL의 원본 실수 값을 낮은 정밀도로 덮어쓰지 않았습니다.

수치·해시 증거는 [이관 검증 자료](postgresql-migration-2026-10-19.json)에 있습니다.
제거한 구 실행기·평가 파일·문서 원문과 호환되지 않는 로컬 테스트는
`db1_regional_archive.source_archive`에 바이트 원문과 SHA-256으로 보존했습니다.
보존 내용을 다시 조회해 검증한 뒤 로컬 원본을 제거했습니다.
기존 DB 파일 2개(478,932,992바이트)도 전체 검증 후 제거했습니다. 보존 원문은 총 82개이며,
그중 호환되지 않는 로컬 테스트·종속 파일과 임시 UI DB 32개를 원문 검증 후 정리했습니다.

## 코드·설정

- 공통 분석 연결, 스키마 검사, 읽기 전용 연결, 중첩 트랜잭션, advisory lock을 적용했습니다.
- 쿼리 매개변수, UPSERT, 날짜·JSON·집계·테이블 검사·자동 증가 이력 ID를 PostgreSQL 문법으로 전환했습니다.
- 게시기는 작업 스키마의 고정된 읽기 스냅샷에서 버전별 서비스 테이블로 배치 적재합니다.
- `--db`는 전용 작업 스키마 이름이며 서비스 전달본 검사기는 `--workspace`를 받습니다.
- 기존 DB 파일의 LFS 연결 및 관련 ignore 규칙을 제거했습니다. 테스트의 Git 제외 규칙은 유지했습니다.
- 원천 CSV·XLSX, 모델, 서비스·업무·복지 데이터는 보존했습니다.

## 확인한 동작

- 107개 테이블 전체 행 및 38개 뷰 비교.
- 새 작업 스키마 초기화, 정상 저장·예외 롤백, 중첩 연결, UPSERT, 읽기 전용 쓰기 거절.
- 실제 자료 복제 스키마에서 분석 DDL·설문 뷰 재생성 및 이력 identity 저장.
- CSV 내보내기와 화면 집계 생성: 지역 유형 22행, 소비 맥락 1,320행, 설문 맥락 144행.
- 서비스 전달본 검사: 월별 770행·지역 구조 22행, 모델 `analysis1_2025H2_elder_v2`, `published=false`.
- 격리한 게시 스키마에서 버전 게시 및 지역 저장소 22개 동 조회. 검증 스키마는 제거했습니다.
- 보존 원문 복원 시 해시 검사 및 기존 파일 덮어쓰기 방지.
- 프런트엔드 Vite 빌드.

전체 원천자료의 새 연도 재계산이나 외부 AI 호출 품질 검증은 이번 이관 검증에 포함하지 않았습니다.
기존 기능의 별도 확인 항목은 [구조 정리 기록](repository-cleanup-2026-10-19.md)에 남겼습니다.
다른 지역 복지사업은 관할 지역의 도입 참고로 추천할 수 있으며, 지역·이용 조건은 구분해서 안내합니다.

설치된 Python·서드파티 패키지의 내부 구현과 브라우저 임시 프로필, Git 과거 이력은 애플리케이션 소스 정리 대상이 아닙니다.
현재 실행 방법과 복원 명령은 [저장소 안내](postgresql-storage.md)를 참고하세요.
