# 코드·파일 최종 재점검 (2026-10-21)

기준은 `HyungWoo_React`의 `33a96ce`이며, 시작할 때 작업 트리는 깨끗했습니다.
기존 화면·API·분석 기준을 유지하면서 관리 파일 593개를 조사했습니다.
공유 DB 변경, 외부 AI 호출, 커밋·push·배포는 수행하지 않았습니다.

화면에서 직접 호출하지 않아도 독립 실행·검증·복원 용도가 있는 도구는 유지했습니다.
기준 모델 생성·분석 검증에 재사용할 수 있는 `run_analysis1`, 공개본 복원용 `activate`,
검색 캐시 초기화용 `clear_cache`도 단순 참조 횟수만으로 제거하지 않았습니다.

## 가독성 개선

- 관리 중인 Python 221개와 JavaScript·JSX·CSS 69개를 대상으로 문장 배치와 들여쓰기를 점검했습니다.
- Python은 4칸 들여쓰기와 100자 줄 길이를 기준으로 압축된 조건문·함수 호출·자료 구성을 펼쳤습니다.
  한 줄의 여러 import도 분리했습니다. 화면 코드와 CSS는 같은 100자 기준으로 정돈했습니다.
- 지역 유형 기준 모델·변화 비교의 `f`, `b`, `c`, `cur`, `res` 등을 `feature_frame`,
  `balanced_features`, `clusters`, `current_features`, `changes`처럼 역할이 보이는 이름으로 바꿨습니다.
- PCA 변환을 원본값 → 표준화값 → PCA 점수 순서로 풀고, 이미 읽은 모델을 다시 검사하던 중복 단계를 줄였습니다.
- 화면의 중첩 조건식과 보고서 수치 대조를 단계별 조건문·중간값으로 풀었습니다.
- 정의되지 않았던 `QueryIntent` 타입 import를 보완하고, 외부에서 쓰는 DB 예외·전처리 함수 export는 명시했습니다.
- [개발 안내](../development-guide.md)에 React 화면·분석 읽기 순서와 자주 나오는 용어를 보탰습니다.

포맷 정리에는 임시 도구 Ruff 0.14.14와 Prettier 3.6.2를 사용했습니다.
서비스 의존성 목록은 변경하지 않았습니다. 알고리즘·SQL·자료 스키마·서비스 폴더 경계는 유지했습니다.
수학·비동기·동시성 자체를 없애는 대신, 필요한 처리의 이름·순서·설명을 드러내는 방식입니다.

## 재점검 도구 개선

`scripts/audit_repository.py`는 이제 `frontend/src/main.jsx`에서 실제 import를 따라갑니다.
서로만 참조하고 화면 시작점과 연결되지 않은 파일 묶음도 후보로 찾습니다.
동적 import와 CSS import도 기존과 같이 조사합니다. 후보는 자동 삭제하지 않습니다.
