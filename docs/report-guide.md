# 보고서 작성 안내

보고서 작성 탭과 챗봇은 `backend/agents/report_writer.py`의 같은 에이전트를 호출합니다.
검토 요지, 지역 현황, 복지서비스 연계·추진 제안, 향후 조치의 네 항목으로 작성합니다.
적합은 연계 가능성 제안, 보류는 조건 확인 후 재검토, 부적합은 제안에서 제외로 구분합니다.
변화 원인이나 개인의 사업 자격, 확정된 추진 계획을 생성하지 않습니다.

## 두 단계 작성

1. **기초 초안**: 외부 AI를 호출하지 않고 서버 자료만으로 문장을 구성합니다.
   - `generate_draft`: 저장된 분석 수치와 사업 검토 기록(업무 기록)으로 만든 초안
   - `conversation_draft`: 보미 대화에서 찾은 기존 사업과 최근 신규 사업 구상안, 이 동의 분석 수치로 만든
     «대화 기반 초안 · 담당자 검토 전». 신규 구상안에는 «운영 중인 사업 아님»을 붙입니다.
2. **AI 문장 다듬기**(`polish`, 선택): AI가 기초 초안을 공문서 개조식 문체로 다듬고, 담당자 요청("더 간결하게" 등)을 반영합니다.
   보고서 탭의 «AI로 문장 다듬기»(기본 꺼짐)를 켜거나, 보미의 AI 스위치가 켜져 있을 때 적용됩니다. 관리자가 «AI 설정»에서 허용해야 합니다.

AI 문장은 `check_grounding`으로 기초 초안과 대조하고, 아래 중 하나라도 해당하면 버리고 기초 초안을 씁니다(화면에 이유 안내).

- 기초 초안에 없는 숫자(금액·날짜·연락처 포함)나 URL이 생김. 숫자는 같은 항목의 초안에 있어야 함(검토 요지는 초안 전체 기준)
- 기초 초안에 없는 한글 수량 표현(세 곳, 두 배, 대부분 등)이 생김
- 팀 복지사업 자료의 사업명·기관명 중 초안에 없던 이름이 생김
- 원인·결과를 단정하는 표현(때문, 로 인해, 확정, 확인됨 등)이 초안보다 많아짐
- 제안 항목의 사업이 빠지거나 판단·표시 문구(연계 가능성 검토 제안 / 운영 조건 확인 후 재검토 / 현재 연계 제안에서 제외 / 담당자 검토 전 / 운영 중인 사업 아님)가 바뀜
- 세부 줄('- 지원 내용:', '- 검토 근거:' 등)이 빠지거나 합쳐짐, 또는 안내 원문 링크가 빠짐
- 판단 문구가 다른 사업으로 옮겨짐(각 사업은 '사업명: 판단 문구' 순서로, 다음 사업 이름 전에 문구가 있어야 함)
- '개인의 고립 여부나 변화 원인을 확정할 수 없음' 문장이 빠짐
- 항목이 비거나 글자 수 상한을 넘음, 또는 AI 호출·응답 형식 오류

AI 문장을 버리면 안내 문구에 대표 이유를 3개까지 보여 줍니다(예: "이유: 검토 요지: 근거에 없는 숫자 5,000").

대조는 새 사실이 들어오는 것을 막는 장치이며 문장의 뜻까지 보장하지 않습니다. 담당자가 내용을 검토한 뒤 저장해야 합니다.

Word 파일에서 검토 요지는 맨 위 요약 상자에만 들어가고, 본문은 지역 현황부터 시작합니다.

## 사용

1. 보고서에 포함할 분석 지표와 사업을 선택합니다. 사업 검토 기록 없이 분석·대화·구상으로도 작성할 수 있습니다.
2. 보고서 탭에서 「보고서 초안 만들기」를 누릅니다(«AI로 문장 다듬기» 선택 가능).
   챗봇에 「보고서 초안 만들어 줘」, 「보고서 작성해줘」처럼 요청해도 같은 에이전트가 초안을 만듭니다.
   챗봇에서 사업을 찾거나 신규 사업을 구상한 직후라면 그 대화 내용으로 «담당자 검토 전» 초안을 만듭니다(검토 기록 없이도 가능).
3. 챗봇 답변의 「초안을 보고서 탭에서 수정」을 눌러 편집을 이어갑니다.
4. 부서·작성자·선택 연락처와 본문을 검토하고 Word 파일을 생성합니다.
5. 다운로드한 문서를 확인한 후 최종 확인과 저장을 수행합니다.

작성 중인 본문은 계정·지역·기준월별로 브라우저에 임시 보관됩니다. 최종 저장 문서는 업무 기록 저장소에 보관됩니다.
최종 저장 후 본문·다운로드 초안·확인 체크를 초기화해 같은 지역의 보고서를 다시 작성할 수 있습니다.
작성 부서·작성자·연락처는 화면에서 유지됩니다. 재작성 중에는 기존 저장본을 계속 다운로드할 수 있습니다.
다시 최종 저장하면 최신 다운로드가 갱신되고 이전 파일과 작성 기록은 PostgreSQL `work.report_versions`에 보관됩니다.
보고서 재작성은 저장된 근거와 사업 검토를 재사용하며, 이전 보고서 파일은 저장 차수 목록에 남깁니다.
사업 검토가 바뀌면 제안 갱신으로 초안의 근거 버전을 맞춥니다. Word 확인본 생성 후 검토가 바뀌면 다시 생성해야 합니다.
초안 생성·근거 조회만으로 업무를 저장하거나 완료하지 않습니다.
1~2쪽을 목표로 간결하게 작성하며, 입력 길이·출처·폰트 환경에 따라 쪽수가 늘어날 수 있습니다.

## 연결 구조

`frontend/src/App.jsx → backend/api/routes_work.py → backend/agents/report_writer.py` 경로로 보고서 초안을 작성합니다.
Word 파일은 `backend/services/report.py`에서 생성합니다. 보미의 보고서 요청은 `backend/api/routes_chat.py → backend/bomi/pipeline.py → backend/bomi/agents/report.py → backend/agents/report_writer.py` 경로로 같은 초안 함수를 호출합니다.
챗봇 구조는 [보미 챗봇 안내](../backend/README.md#bomi)를 참고하세요.

- `POST /api/report/content`: 서버에 저장된 기록으로 편집용 초안 생성(`ai: true`이면 AI 문장 다듬기)
- `POST /api/chat`: 보미가 분석·복지사업·보고서·안내 중 담당을 골라 답변
- `POST /api/report/preview`: 편집 내용 검증, 템플릿 DOCX 생성, 사용자별 임시 토큰 발급
- `POST /api/report/proposal`: 나머지 편집 내용을 유지하며 제안·사업 검토 근거 갱신
- `GET /api/report/material`: 포함할 근거 조회(저장하지 않음)
- `GET /api/report/versions`: 저장 차수 목록
- 다운로드·최종 저장 API: 지역·사용자·사업 검토 버전 및 파일 해시 검사

첨부 문서의 안내와 예시는 서식 참고 자료입니다. 문서 안의 행사·일정·연락처는 보고서에 복사하지 않습니다.
기본 템플릿은 `backend/resources/templates/약식보고서_서식_보고서.docx`, 서식 적용은 `backend/services/report.py`에 있습니다.
템플릿 문서가 누락되면 다른 양식으로 대체하지 않고 생성 오류로 안내합니다.
