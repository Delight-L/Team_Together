## 체험 순서

1. 로그인하고 상단 **이용 안내 → 체험·업무 안내 → 독립 체험 시작**을 누릅니다. 기존 업무를 유지하면서 이번 체험의 새 기록 공간을 만듭니다.
2. 상단 **이용 안내**를 열고 **3~5분 체험 안내 보기 → 분석 가능한 지역으로 시작**을 누릅니다.
3. 지표·출처·기간을 읽고 **분석 확인 저장 → 근거 검토 완료**를 진행합니다.
4. **사업 매칭 검토**에서 실제 사업을 조회하고 대상과 조건을 확인한 뒤 검토 결과를 저장합니다.
5. **보고서 작성**에서 초안을 편집합니다. 보조 점검과 Word 파일을 확인하고 최종 저장합니다.
6. **검토·후속 조치**에서 확인 사항, 담당자, 기한, 실제 조치와 다음 달 확인할 내용을 저장합니다.
7. **지역·기간 비교**에서 여러 동의 변화를 보고, 월별 후속 조치 기록과 대조합니다.
8. 상단 **이용 안내 → 체험 의견**에서 막힌 단계와 추가 요구를 기록합니다.

**새 체험 시작**은 기존 기록을 삭제하지 않고 새 공간으로 전환합니다. **기존 업무로 돌아가기**는 로그인 계정의 업무로 복귀합니다. 체험 공간에서는 데이터 업로드와 관리자 기능을 사용할 수 없습니다.

종합현황에는 지도·핵심 지표·주요 변화만 배치합니다. 체험/업무 안내, 데이터 기준, 체험 의견은 상단 이용 안내 버튼으로 여는 모달 안에 제공합니다. 종합현황 본문의 높이를 늘리지 않으며, 1280×800 화면에서 본문 스크롤 없이 표시되는 것을 확인했습니다.

## 저장과 협업 범위

- 기존 로컬 SQLite 파일에 별도 `experience`, `experience_feedback` 테이블을 생성합니다. 기존 업무와 보고서는 변경하지 않습니다.
- 업무 기록은 지역·동·기준월별로 공유합니다. 체험 기록은 체험 ID별로 분리합니다. 소속 지역 접근 검증을 서버에서 수행합니다.
- 저장 시 버전을 검사합니다. 다른 담당자가 먼저 저장했다면 덮어쓰기를 차단하며, 최신 기록을 불러온 뒤 다시 편집해야 합니다.
- 담당자 지정과 인계는 기록 기능입니다. 외부 메일·메신저나 자동 기한 알림을 발송하지 않습니다.
- 입력 중 내용은 저장 버튼을 눌러야 영구 반영됩니다. 최신 기록 다시 불러오기는 현재 편집 내용을 저장된 값으로 바꿉니다.
- 세션은 기존 서버와 같이 메모리에 있습니다. 서버 재시작이나 로그아웃 후 같은 독립 체험을 자동 복원하지 않습니다. 이전 체험 기록은 DB에 남습니다.

## 검증

```powershell
cd frontend
npm run build
npm run test:map
node tests/check-experience.mjs
cd ..
.venv/Scripts/python.exe -m unittest discover -s webapp/tests -v
```

API 검사는 임시 SQLite를 사용합니다. 체험 전환·초기화·기존 업무 복귀, 공유 기록, 변경 충돌, 지역 권한, 관리자 권한, 피드백 입력 검사와 기존 보고서 흐름을 포함합니다. UI 확인은 별도 임시 업무 DB를 연결하여 수행했습니다.

## 데이터와 운영상 한계

- 현재 실제 분석 결과는 강남구에 연결되어 있습니다. 춘천시는 실제 분석 파일이 연결되어야 분석 업무를 진행할 수 있습니다.
- 파일 변경 시각과 연결 확인 시각은 원천자료의 수집·갱신일을 의미하지 않습니다.
- 실제 사업 조회는 기존 DB2 연결 및 수집 자료에 의존합니다. 접수 가능 여부와 이용 자격은 운영기관에 확인해야 합니다.
- 보고서 점검은 백분율과 저장된 값의 대조 및 일부 표현 검사입니다. 모든 수치·문장 의미를 자동 검증하지 않으며, 사업 지원 비율 등 별도 출처의 숫자는 추가 확인 대상으로 표시될 수 있습니다.
- 후속 조치와 월별 지표를 비교할 수 있지만 조치의 인과적 효과를 판정하지 않습니다.
- 공용 서비스 배포 시 기존 시연 인증을 운영 인증으로 바꾸고 세션 저장소·HTTPS를 별도로 구성해야 합니다.
