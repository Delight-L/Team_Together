# 약식보고서 작성

보고서 작성 탭과 챗봇은 `agents/report_writer.py`의 같은 에이전트를 호출합니다.
기본 초안은 저장된 분석 설명과 담당자의 사업 검토 기록을 구성하며 외부 AI를 호출하지 않습니다.
검토 요지, 지역 현황, 복지서비스 연계·추진 제안, 향후 조치의 네 항목으로 작성합니다.
적합은 연계 가능성 제안, 보류는 조건 확인 후 재검토, 부적합은 제안에서 제외로 구분합니다.
변화 원인이나 개인의 사업 자격, 확정된 추진 계획을 생성하지 않습니다.

## 사용

1. 분석 근거 확인과 사업 매칭 검토 기록 저장을 완료합니다.
2. 보고서 탭에서 「보고서 에이전트로 초안 만들기」를 누릅니다.
   챗봇의 「약식보고서 초안 만들기」 또는 「보고서 작성해줘」도 같은 초안을 만듭니다.
3. 챗봇 답변의 「초안을 보고서 탭에서 수정」을 눌러 편집을 이어갑니다.
4. 부서·작성자·선택 연락처와 본문을 검토하고 Word 파일을 생성합니다.
5. 다운로드한 문서를 확인한 후 최종 확인과 저장을 수행합니다.

본문 편집은 화면을 떠나면 유지되지 않습니다. 최종 저장 문서는 기존 업무 DB에 보관됩니다.
최종 저장 후 본문·다운로드 초안·확인 체크를 초기화해 같은 지역의 보고서를 다시 작성할 수 있습니다.
작성 부서·작성자·연락처는 화면에서 유지됩니다. 재작성 중에는 기존 저장본을 계속 다운로드할 수 있습니다.
다시 최종 저장하면 최신 다운로드가 갱신되고 이전 파일과 작성 기록은 SQLite `report_versions`에 보관됩니다.
완료된 분석·사업 검토 기록은 계속 잠금 상태이며, 보고서 재작성은 해당 근거를 재사용합니다.
사업 검토 기록이 바뀌면 초안을 다시 생성해야 합니다. 생성만으로 업무를 완료하지 않습니다.
1~2쪽을 목표로 간결하게 작성하며, 입력 길이·출처·폰트 환경에 따라 쪽수가 늘어날 수 있습니다.

## 연결 구조

`React → webapp/server.py → chatbot/orchestrator.py → 전문 에이전트` 구조입니다.
Chatbot_Test의 클라이언트 분리 구조를 반영해 `chatbot/llm/client.py`에 AI 제공자 호출을 분리했습니다.
기존 Gemini 설정과 로그인·업무 API를 유지하며 FastAPI 서버를 별도로 실행할 필요가 없습니다.
현재 대화 응답은 기존 JSON 방식입니다. Chatbot_Test의 SSE 스트리밍은 아직 이식하지 않았습니다.

- `POST /api/report/content`: 서버에 저장된 기록으로 편집용 초안 생성
- `POST /api/chat`: 기본 안내·자유 대화·보고서 초안 요청 분기
- `POST /api/report/preview`: 편집 내용 검증, 템플릿 DOCX 생성, 사용자별 임시 토큰 발급
- 기존 다운로드·최종 저장 API: 지역·사용자·사업 검토 버전 및 파일 해시 검사 유지

첨부 문서의 안내와 예시는 서식 참고 자료입니다. 문서 안의 행사·일정·연락처는 보고서에 복사하지 않습니다.
기본 템플릿은 `docs/약식보고서_서식_보고서.docx`, 서식 적용은 `shared/report.py`에 있습니다.
템플릿 문서가 누락되면 다른 양식으로 대체하지 않고 생성 오류로 안내합니다.
